# HedgeGuard v2 Numeric and Negation Validation Flag Analysis

## Executive summary

**Observed:** The latest saved report covers 165 candidates: 0 eligible, 4 excluded, 161 review-required, and 0 rejected. It records 78 numeric-difference flags and 12 negation-difference flags. I independently selected 78 rows from the saved derived CSVs with the numeric flag and 12 with the negation flag, including excluded rows.

**Interpretation:** Many flags are useful alarms, but the checks are lexical and operate on full sentence pairs without aligning individual numeric or negated claims. They mix possible claim changes with citations, DOI/table numbers, extra or omitted details, and numbers referring to different propositions. Negation flags likewise show marker differences, not necessarily changed polarity. The pilot has examples of both useful warnings and likely false positives, but has no human adjudications; this report does not assign ground-truth labels.

**Read-only scope:** Only this report was written. Existing CSVs, JSON, and source code were read only. No Ollama/LLM, test, collection, model-training, or split operation was run.

### Negation interpretation

**Primary categories (analyst assessment):** 0 clear aligned polarity reversals; 1 technical-term/negation confound; 1 possible negation removal without apparent change to the central distinction; 2 unrelated clause/context cases; 7 different propositions; 1 unclear case. These are descriptions of flagged comparisons, not gold labels.

The implementation compares sentence-wide marker counters first. If they differ, it immediately returns `mismatch`; it does not align the marker to a Stage A proposition or test whether both clauses state the same claim. A rough clause-scope signature is computed only when the marker counters match. That signature uses punctuation boundaries and nearby tokens; it is not proposition alignment. Multiple markers produce `uncertain`; “not only” and “not just” are ignored.

## Implementation findings

### Numeric functions

In `src/dataset/real_world.py`:

1. `_numeric_mentions(text)` applies `_RANGE_RE` for ranges, blanks those spans, then applies `_NUMBER_RE` for remaining values and optional units. Supported units are `%`, `percent`, `mg`, `ml`, `kg`, `cm`, `mm`, years, months, and days.
2. `_decimal(value)` strips commas and normalizes with `Decimal`. Values such as `1,170` and `1170` compare equally, though display strings can use scientific notation.
3. `compare_number_mentions(source, summary)` compares unordered `Counter`s of point and range tuples. It does not represent nearby metric, numeric role, clause, citation status, or proposition. A single exception accepts a complete evenly spaced list versus an endpoint range with matching units (e.g. 10%, 20%, …, 50% vs 10%-50%). Otherwise any extracted addition, omission, change, or unit difference is `mismatch`.
4. There is no exclusion for citation markers, years, table/figure labels, numbered list items, URLs, or DOI strings. Bare years intentionally count as numbers, distinct from `compare_calendar_dates`. DOI paths and hyphenated identifiers can be parsed as numeric fragments. Only `percent` maps to `%`; ratio-to-percentage and other unit conversions are not handled.
5. `validate_real_world_rows` runs the comparison on whole `source_sentence` and `summary_sentence`, regardless of Stage A alignment. Mismatch adds a review flag; it does not itself approve or exclude a row.

### Negation functions

`_NEGATION_RE`, `_negation_markers(text)`, and `compare_negation(source, summary)` perform this check:

- Exact marker matching from a fixed list; “negative” is not included.
- Whole-sentence marker extraction, with a small exception for `not only`/`not just`.
- Multiple markers → `uncertain`; different marker counters → immediate `mismatch`.
- Equal markers then get rough clause signatures using `.`, `;`, and `,`, plus three preceding and four following tokens. Signature mismatch → `uncertain`.
- The validator applies it to the full source and summary sentences; it never requires aligned propositions before reporting a mismatch.

## Recommendations (not implemented)

1. **Align propositions before interpreting mismatches.** Use exact Stage A spans only when comparability is established; if alignment is uncertain, keep review-required. *Example:* do not compare “not included” with a supplement notice. *Risk:* faulty spans can hide changes; exact quote validation and conservative fallback are necessary.
2. **Separate claim quantities from metadata.** Parse citations, DOI/URL fragments, table/figure labels, and list enumerators separately, while preserving years and values that belong to a claim. *Example:* `[2]`, `Table 1`, and DOI digits should not behave like changed cohort sizes. *Risk:* broad stripping can remove meaningful sample numbers or years; use syntax-aware recognition and audit it.
3. **Compare numeric roles and units, not unordered bags.** Link values to nearby metric/quantity terms (N, AUROC, AUPRC, κ, CI, year, percent) and preserve range endpoints. Add narrow math equivalence checks for validated forms such as `<0.70` vs “more than 30% lower.” *Example:* distinguish κ 0.000 vs 0.231 for the same variable from extra subgroup counts. *Risk:* denominator, direction, CI, and unit errors; only compare forms when metric, scope, and denominator match.
4. **Separate changed values from added/omitted values.** Keep missing or extra details as review signals without claiming a contradiction. *Example:* retain a warning for omitted 42/30 comparator counts while recognizing the 62/43 comparison remains. *Risk:* an omitted population restriction can be central, so no automatic clear/approval.
5. **Scope negation to an aligned predicate.** Distinguish domain terms from negation and compare polarity only for the same claim. If a negator occurs in an unaligned clause, return uncertain/review. *Example:* `negative discordance` should not be a negation cue; “not apparent” should be interpreted with its predicate. *Risk:* negation can be expressed by “absence,” “insufficient,” or cross-clause scope; preserve abstention for ambiguity.
6. **Add paired regression tests for observed patterns.** Cover same-variable value changes, dropped age limits, equivalent ratio/percent thresholds, citations/DOIs/table numbers, list numbering, `negative discordance`, `not apparent`, `without refitting`, and multiple clauses. Assert ambiguous cases remain review-required. *Risk:* overfitting a small fixture set; vary phrasing and units.

## Limitations and unresolved questions

- The pilot has no human-reviewed labels for these pairs. Numeric and negation categories describe flag behavior, not correctness of the source/summary match or any label.
- Many rows already have Stage A `uncertain`; a token mismatch there cannot establish that one shared proposition changed.
- Semantically similar same-document sentences can have different roles/claims; similarity is retrieval-only.
- Numeric tuples are unordered, so this analysis cannot infer which metric or subject an extracted value belongs to without manual context.
- 78 numeric and 12 negation flags overlap; reason counts are not disjoint example counts.
- This read-only analysis neither changes validation policy nor marks records eligible.
